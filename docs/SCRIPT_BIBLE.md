# UNDERFAIL 대본 제작 바이블

## 문서 상태

- 상태: `Proposal`
- 적용 범위: 사용자가 `chat.json`에서 마지막으로 확정·수정한 캐릭터와 세계관 요소
- 결말부: 불리의 최종 기능, 저장·재시작의 세계관 의미, 강경·평화·숨겨진 결말은 보류
- 정사 기준: [CURRENT_CANON_BASELINE.md](./CURRENT_CANON_BASELINE.md)
- 구조·기술 기준: [UNDERFAIL_SYSTEMS_TECHNICAL_REPORT.md](./UNDERFAIL_SYSTEMS_TECHNICAL_REPORT.md)
- 본편 진행 순서: [STORY_PROGRESSION_MAPPING.md](./STORY_PROGRESSION_MAPPING.md)
- 현재 본편 대본: [STORY_SCRIPT.md](./STORY_SCRIPT.md)

이 문서는 완성 대본이 아니라, 최신 기준선에서 대사를 생산하기 위한 규칙과 장면 계약이다. 이전의 결말 직전 전체 대본 초안은 폐기했으며, 승인되지 않은 장면·이름·대사는 정사로 취급하지 않는다.

## 1. 대본의 핵심 원칙

### 1.1 원작에서 가져오는 것

- 모든 만남에 전투 외 해결 가능성을 둔다.
- `관찰 → 행동 → 반응 → 재방문`으로 캐릭터의 성향을 플레이어가 발견하게 한다.
- 전투 패턴은 공격 기술이 아니라 상대의 직업·욕망·불안을 시각화한다.
- 루트는 한 번의 선택이 아니라 처치, 비전투 해결, 관계, 탐색, 재방문의 누적이다.
- 유머 장면은 분위기 완화만이 아니라 인물의 방어기제와 후속 변화를 드러내야 한다.

### 1.2 복제하지 않는 것

- 원작의 대사, 고유 장면, 고유 맵, 음악, 공격 패턴, 고유 명칭을 옮기지 않는다.
- 원작 인물의 말투를 문장 단위로 흉내 내지 않는다. 대신 말의 기능을 분석해 UNDERFAIL 인물의 직업과 목표에 맞춰 새로 쓴다.
- 원작의 SAVE·RESET 메타 해석을 승인 없이 UNDERFAIL의 세계관 사실로 확정하지 않는다.

## 2. 장면 계약

모든 장면은 다음 형식을 따른다.

```text
[SCENE scene_id]
상태: Canon 기반 / Proposal
장소·시점:
등장인물:
장면 목표:
플레이어가 알 수 있는 것:
플레이어가 아직 몰라야 하는 것:
조사 대상:
선택지:
대사 기능:
상태 변화:
재방문 변화:
복선:
```

장면 하나에 새 핵심 설정을 두 개 이상 도입하지 않는다. 대사는 한 번에 세계관을 설명하지 않고, 조사·선택·재방문에서 서로 다른 의미를 제공한다.

## 3. 대사 설계

### 3.1 인물별 대사 기능

| 인물 | 말의 표면 | 숨은 기능 | 피해야 할 것 |
|---|---|---|---|
| 도미토리엘 | 따뜻한 보호와 생활 안내 | 보호가 통제로 변하는 순간을 감춤 | 처음부터 모든 과거 설명 |
| 아스도어 스톨민트 | 합리적이고 안정적인 제안 | 실패 공포를 정책으로 정당화 | 단순 악역 선언 |
| 불리 | 위험한 자유와 조롱 | 주인공의 판단을 시험하고 가족 문제를 비춤 | 최종 정체 조기 공개 |
| 파프리카 | 과장된 수업 진행과 실적 걱정 | 학생 보호와 직업 안정의 충돌 | 무능한 개그 보스 |
| 체임버쌤 | 규칙·안전·현장 책임 | 질서가 학생을 보호하는지 검증 | 폭력적인 추격자만으로 고정 |
| SANZ | 짧은 농담과 관찰 | 방관의 책임, 행동 기록의 의미 | 원작 대사의 직접적 말투 복제 |
| 알파이썬 | 기술 설명과 불안 | 선의의 발명과 책임 회피의 충돌 | 만능 해설자 |
| 모델스 튜던트 | 공부 방해에 대한 과잉 반응 | 타인의 의도를 자기 기록으로 덮어씀 | 단순한 광인 표현 |
| 너드스타블룩 | 취향을 숨기는 짧은 말 | 취향 공개가 관계를 바꾸는 순간 | 계속 같은 우울 농담 |
| 디버그 스톤 | 오류의 정의를 묻는 말 | 정보와 책임의 경계 | 초월적 진실의 조기 확정 |

### 3.2 대사의 세 층

1. **즉시 이해층:** 플레이어가 지금 해야 할 행동을 알 수 있다.
2. **성향층:** 인물이 왜 그 행동을 하는지 추측할 수 있다.
3. **후속층:** 나중에 같은 문장이나 물건이 다른 의미로 돌아온다.

중요한 사실은 대사 한 줄로 확정하지 않는다. 최소 두 개의 행동 결과나 기록과 결합될 때만 확정 정보가 된다.

## 4. 본편 대본 작성 순서

1. [CURRENT_CANON_BASELINE.md](./CURRENT_CANON_BASELINE.md)에서 사용자 확정·보류를 확인한다.
2. [STORY_MASTER_BIBLE.md](./STORY_MASTER_BIBLE.md)의 장 기능만 가져오고, 세부 대사는 새로 작성한다.
3. 각 장의 일반 만남 3개, 지역 퍼즐 1개, 주요 대립 1개, 재방문 1개를 설계한다.
4. 주요 대립마다 비전투 해결 조건과 강제 제압 결과를 별도로 쓴다.
5. 대사·상태·재방문을 데이터 ID로 연결한다.
6. 마지막에 원작 유사 문구, 승인되지 않은 이름, 결말 확정 문장을 점검한다.

## 5. 장면 데이터 최소 계약

```text
sceneId
chapter
location
participants
requires
dialogueBlocks
choices
effects
returnVisit
foreshadows
```

`requires`가 충족되지 않을 때 조용히 기본 장면으로 대체하지 않는다. 조건 불충족 이유를 UI와 개발 로그에 표시하고, 대체 장면은 명시적인 `fallbackSceneId`로 정의한다.

## 6. 현재 본편 대본

[STORY_SCRIPT.md](./STORY_SCRIPT.md)는 원작의 등장 순서·사건 기능·루트 논리를 UNDERFAIL의 최신 기준선에 맞춰 새로 작성한 Proposal 대본이다. 원작 대사의 복제나 근접 변형이 아니라, 대응 인물의 역할과 학교 세계관의 사건으로 작성한다.
